## Important distinctions

- The preview is connected to the real .NET API, but the running persistence adapter is the development-only in-memory Demo adapter. Restarting the API resets synthetic data.
- The SQL adapter compiles and migration 0003 passes static TSQL parsing. No SQL Server instance was available in this environment, so no claim is made that Phase 3 migrations or queries have executed successfully. `tests/Careflow.SqlTests` runs the Phase 1–3 database gate in the CI `sql-integration` job.
- **No live modality, PACS or DICOM connection exists or is claimed.** The RIS slice stores Study Instance UIDs and status transitions only. The viewer-launch endpoint fails closed until an approved integration is configured, and the `pacs` module cannot be enabled.
- Radiology authorization enforces separation of duties (authorizer ≠ reporter), mirroring LIS validation. Finalized reports are immutable; addendum/corrected-report workflows are planned.
- Blood compatibility is enforced server-side with a component-aware matrix (red cells: O donor universal; plasma: AB donor universal; Rh-positive never to Rh-negative). This is a decision-support rule, not a substitute for the bank's SOP or crossmatch procedure.
- Emergency dispositions are single-shot per episode: an episode with a disposition is closed and refuses further triage/observations. Admit requires a linked registered patient, an available bed and a responsible practitioner; Refer requires a receiving facility.
- Theatre scheduling enforces single-booking overlap per theatre in the service layer (and the SQL gate tests the same rule). Recurrence, block timings and surgeon-parallel constraints are planned.
- Workspace and chart care lists are bounded and expose truncation warnings. They are not complete archives.
