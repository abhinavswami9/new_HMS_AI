## Important distinctions

- The preview is connected to the real .NET API, but the running persistence adapter is the development-only in-memory Demo adapter. Restarting the API resets synthetic data.
- The SQL adapter compiles and migration 0005 passes static TSQL parsing. No SQL Server instance was available in this environment, so no claim is made that Phase 5 migrations or queries have executed successfully. `tests/Careflow.SqlTests` runs the Phase 1–5 database gate in the CI `sql-integration` job.
- **NABH/NABL-oriented evidence, not accreditation certification.** Quality incidents, CAPA, controlled documents and indicators are structured evidence records with separations and audit trails. Nothing in this system certifies, claims or substitutes for NABH or NABL accreditation.
- **No arbitrary user SQL.** Reports select from a server-side query registry; definitions store query keys and declared columns/filters only. `report.query` rejects anything else.
- **No payment gateway.** Portal payments are ledger entries against the owned invoice with traceable references and cumulative caps; they are not bank or payment-service transactions.
- **The portal device session is Careflow's own ephemeral token** (SHA-256-hashed at rest, explicit expiry and revocation) — it is not an SSO session, and no external identity provider is integrated or claimed. Identity proofing is recorded evidence (e.g. ID reference plus in-person desk verification) verified by a second person.
- Separation of duties is enforced: the version author cannot approve their own document (`quality.separation`), the definition owner cannot approve their own report definition (`report.separation`), CAPA effectiveness is verified before closure, and incidents cannot close while CAPA actions remain open.
- Portal record access is deny-by-default: an account reaches a record only as its owner, through an active patient link, or through an unexpired proxy grant that includes the needed scope. Downloads are allowed only for authorized results and are audited with a watermark.
- Report parameters are `from`/`to` dates only, bounded to 366 days; exports inherit the caller's data access and carry a `Careflow HIS` watermark with requester and timestamp.
- Dashboard metrics are computed at request time over the same governed data and labelled with freshness and provisional flags — provisional values may differ from month-close figures.
